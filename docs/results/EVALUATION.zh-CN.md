# ChangeBench 首批实测结果评估

评估对象：v0.3 修复后的 24 条 Python 原冻结轨迹，以及随后的四段恢复记录。评估日期：2026-10-20。没有新增模型调用；此次仅补做两份原预算终止产物的离线 Docker 功能检查，二者通过。

**结论：可以继续用作功能回归与执行门禁，但目前没有证据支持架构 Skill 收益排名或经过实测校准的能力榜单。原协议显著混入了预算截断与会话完成条件。** 多轮恢复得到的 72/72 是工程闭环结果，不能作为单次冷启动成功率。

五段合计 119 个有结构化记录的阶段执行、855 个唯一完成响应。另有 1 次已经启动、控制进程中断后未形成完整收据的执行，不能把其未知用量填成零。完成响应不等于所有 HTTP 请求次数。

五段已知 Token 合计 **11,489,508**：输入 11,191,086，输出 298,422；输入中缓存量 9,284,197 是子集，不重复相加。输入占总量约 97.4%，输入中缓存占约 83.0%。此外，两轮接入验收已知 186,345 Token；含验收的已知量为 **11,675,853**。本分析不包含更早的 v0.2 实测。

旧基础设施失败阶段已有的 93,832 Token 收据纳入已知量，但该阶段完整用量仍未知。原始 Token 是上下文处理量，缺少提供方账单、缓存定价及中断请求完整用量，实际费用保持未知。

后续配置继续遵循用户授权：本地总量、阶段 Token、agent 时间和工具次数限制均为 `null`；API Key 提供方额度边界未经本地独立核验。离线 Docker 和测试进程限制保留。此次分析未重跑已通过的模型阶段。

## 能证明与不能证明

现有记录支持：这些小型 Python 任务能在这条模型接入链路上得到满足契约的实现，恢复链可以闭环，已有功能测试与磁盘演进检查可以实际执行。保存产物诊断显示，预算终止经常发生在业务代码已能通过测试之后。

它尚不支持以下结论：

- **Skill 带来或不带来收益。** 每个任务族每条件只有一次生成，原协议全链分数有地板，功能诊断有天花板；C 使用暴露有限。维护恢复又是后验选择，不能汇总成原随机效应。
- **等级已经校准。** L1/L2 初版各 3/6 正式完成，L3/L4 各 2/6；每级只有两个任务族，原阶段预算依次为 60k、60k、90k、120k。资源差异与完成条件混在结果中。
- **多语言、多模型泛化。** 真实模型数据仅 Python；TS/Go 原生参考验收不能替代模型实测。调用方宣告模型为 gpt-6.1-sol，Codex CLI 0.159.2、medium，上游不可变模型身份未独立验证。
- **题库已经测出架构能力。** 目前业务源码修复不是恢复的主要变化；需要更有区分度的独立维护任务。公开小型题目可能较易，也可能契约覆盖不足，当前证据不能分离这两者。

## 审计范围与限制

重新核对了原冻结审查、后续三段共 423 个封存文件、855 个唯一响应 ID、72 个正常完成评测组及 46 个终止诊断组的计数、用例集合、种子指纹和进程成功状态；未发现已通过阶段被重复调用。

`retry150` 是缺失完整封存的进程中断段，不能宣称与完整封存段具有同等审计强度。哈希封存只能检查保存文件的一致性，不是可抵御持有者整体重封的独立签名。

成功用例的 `actual` 和进程 `stdout` 未保留，旧记录无法独立重建全部成功语义比较。本次两份补查真实重新执行，其余检查是记录一致性核对，并非对全部候选进行全量重放。48 次业务文件不变通过路径分类和文件内容比较得出，不能解释为架构质量评分。

## 建议的下一步

1. **修评测口径与证据留存。** 分别报告功能正确、正常结束、基础设施与已知用量。在中断时保存并评测产物；新协议可以基于功能合格 T0 开始维护，旧分数冻结。保留成功输出或能独立验证的语义证据。
2. **先检验题库灵敏度。** 新增未用于调题的留出任务，优先跨模块需求变化、组合状态、原始 T0 磁盘兼容和失败回滚。增强有明确语义缺陷的负向控制，检验维护分支是否真的需要生产代码改变。避免靠文件数或主观架构分制造区分度。
3. **固定协议开展新实测。** 从干净初版开始，保持无本地预算；预先固定任务、条件、模型配置与重复安排，失败按预定规则分类，恢复单列。以任务族为配对分析单位，逐步扩展 TS/Go 和第二模型。若要研究强制 Skill 使用，应另设处理组，不改写原 C 的定义。
