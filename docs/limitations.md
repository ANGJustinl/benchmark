# Limitations

- Eight authored new families have correlated ports in three languages. They are
  not 24 independent problems; there are two new families per level.
- Small public tasks do not establish uncontaminated holdouts, production coverage,
  calibrated levels or architecture-quality rankings.
- The original live cohort has 24 Python trajectories, once per family/condition.
  Native TypeScript/Go reference passes are not real model evaluations.
- Provider-declared gpt-6.1-sol / CLI 0.159.2 / medium was used. An immutable upstream
  snapshot was not independently verified; there is no multi-model comparison.
- Cutoffs/completion dominated original formal results. Saved-code recoveries
  changed selection and resources; their 72/72 closure cannot replace old scores.
- C is optional availability; only 2/8 original initial sessions recorded loading.
- Successful actual/stdout values were discarded. Sealed flags, seeds and counts
  support consistency audits, not reconstruction of all semantic comparisons.
  Hashes are not signatures against an owner able to reseal everything.
- One interrupted retry segment lacks complete sealing/receipts. Missing use stays
  unknown. Token counts are not a provider billing statement.
- Public analysis tables are sanitized derived observations. They reproduce
  aggregation, not the original source-file comparison or every Docker execution.
- Docker is a mitigation, not a universal isolation proof. Concurrency, power loss
  and large production systems remain outside scope.
- Historical docs/defaults describe older delivery conditions. Read current setup
  instructions and future protocol changes separately.
