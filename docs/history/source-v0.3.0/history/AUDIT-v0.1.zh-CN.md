# ChangeBench v0.1：测试与审查结论

## 结论

**本地评测工程验收通过；真实模型有效性尚未验收。**

已实现六类任务、A/B/C 配对计划、冷启动维护、双分支快照、独立契约评测、原始成本记录、汇总检查与盲审导出。已提供可接入真实模型的工作进程，但本次没有把参考回放冒充模型实验。

## 实際执行结果

| 证据 | 数量与结果 | 支持什么结论 |
|---|---|---|
| pytest 单元／集成测试 | 136 项通过 | 核心功能、统计约定和异常路径按当前测试工作 |
| 正确参考实现验收 | 36/36 通过 | 六任务 × 三阶段 × 两布局均被接受 |
| 初版语义错误变体 | 6/6 被拒绝 | 覆盖边界判断、折扣舍入、幂等、精度等指定错误 |
| 不修改初版就提交后续需求 | 12/12 被拒绝 | 新需求测试不是仅重复旧契约 |
| 后续功能带旧行为回归 | 12/12 被拒绝 | 新旧契约同时验证 |
| 协议／运行时负向控制 | 7/7 被拒绝 | 假通过、空输出、坏 JSON、重复键、超时、洪泛、崩溃不能算成功 |
| 完整参考回放 | 36 条轨迹、108 阶段，4,410/4,410 契约检查通过 | 计划、角色切换、冻结快照、评分和落盘可以走通 |

73 项校准包括上述正确实现和负向控制；它们与 136 项开发测试有重叠，不能相加作为独立样本。

原始证据在 `results/unit-tests.xml`、`results/pilot/validation.json`、`results/pilot/records.jsonl` 和 `results/pilot/summary.json`。

## 审查中处理的问题

**成本偏差。** API 请求失败后可能已经产生费用，不能记为零。未知 Token 保持 null；缓存和推理 Token 不重复计费；失败尝试保留已知成本。

**实验污染。** B/C 正文统一来源；C 不在初始消息中预装正文。维护阶段清理实验性指令和 Skill，且两分支均使用 T0 的同一快照，避免继承另一分支实现。

**评分失真。** 不允许漏掉失败行、重复行或无声跳过阶段；基础设施错误与模型错误区分。结果中的成功字段需要与阶段证据一致，不凭模型的完成声明计分。

**评测器可被误导。** 评分在候选进程之外；严格检查输出数量、重复 JSON 键、非有限数字、类型和退出状态；限制时间与输出，清理进程组。文件路径拒绝越界、符号链接和文件／目录冲突。

**真实执行安全。** 没有 Docker 时不回退到宿主机执行未知代码；开跑前检查守护进程与本地镜像，并冻结镜像 ID。模型工作进程的工具容器按会话打标，控制进程也负责在工作进程被终止后清理。Docker 相关路径目前只有模拟测试，不能据此声称已完成真实隔离验证。

## 不应从结果得出的结论

A/B/C 回放均通过是预期现象：三组使用的都是正确参考代码，不是三个策略生成出的代码。**不能据此判断三组等价，也不能宣称 design-check 有效或无效。**

本次真实模型调用次数为 0，实际模型 Token 指标未测量。夹具回放中的微秒级“生成时间”只是本地复制参考代码的时间，没有模型效率意义。

## 剩余限制

当前只有六个微型任务族。统一 JSON-lines 与标准库减少了工具链噪声，同时限制了外部效度。状态机原子性测试不等于真实数据库并发测试；模拟提供方不等于外部服务集成测试。

正确布局的两份实现共享参考逻辑；用例和实现出自同一轮构建，尚缺独立规格复核。盲审材料已准备，但没有第二位评审者的实际评分。Python 3.11 与 GitHub Actions 工作流已配置，当前实际运行环境仅验证了 Python 3.13.5。

真实模型、API 通信、Docker 守护进程与容器运行尚未在本环境执行。Token 预算属于响应返回后的检查，不是绝对账单封顶；应额外采用服务方的支出控制。

## 验收建议

将当前版本作为**可复现的评测原型**交付。正式比较前，先完成一条真实模型轨迹的 API/Docker 联调，确认模型工件与成本日志完整，再运行冻结的 36 条计划。只有真实结果显示有辨识度后，才扩展私有任务和模型样本；不要先把它变成一套更复杂的评测平台。
