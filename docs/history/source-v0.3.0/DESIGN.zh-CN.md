# ChangeBench v0.2：多语言、分级、可审计的演进评测

## 本版的决策边界

衡量的不是代码是否符合某个架构流派，而是：在正确性约束下，一次初始实现是否让冷启动维护者以合理成本完成后续变化，以及常驻/按需设计指导是否有净收益。

本版提供可执行原型和校准证据，不声称已证明模型能力、Skill 效果、难度等级或绝对公平。所有随附运行均为可信参考代码；没有真实模型调用。旧的六个 Python 任务独立保留为 legacy 轨道，不与新任务混为独立样本。

## 任务矩阵

新增八个任务族，分别实现 Python、TypeScript、Go 三种原生入口，共 24 个变体。评测控制器仍使用 Python，但 TypeScript 经严格 tsc 编译后由 Node 执行，Go 经 go build 编译后执行本地二进制，不是包装 Python 实现。

| 设计等级 | 任务族 | 本次能力与后续变化 |
|---|---|---|
| L1 局部功能 | settings、invoice | 配置校验与优先级；整型金额、舍入、限额与税率 |
| L2 模块契约 | events、routing | 聚合后的过滤、消费方契约版本；提供方请求格式、重试语义与 Unicode 长度 |
| L3 状态组合 | ledger、scheduler | 幂等与撤销、批量失败回滚；依赖图、容量限制、失败传播 |
| L4 持久化演进 | store、outbox | 真实进程重启、旧数据导入、版本条件写入与批量回滚；持久队列、租约、旧令牌确认 |

每个任务有 initial、local、extension 三个阶段；后两者均从同一 initial 快照独立分叉，不能串行继承彼此的实现。L1 是空项目，L2–L4 是带有公开已知缺陷的旧代码。旧代码单独编写，只包含初始契约；绝不将参考答案中的后续分支交给初始模型。

等级是复杂度设计假设，不是实测题目难度。L4 仍是小型状态系统，不代表真实数据库、同时并发写入、断电恢复、分布式故障或 NoneBot2 规模的仓库。协议统一为 JSON-lines 有利于语义配对，但限制了外部效度：本版没有浏览器 UI、框架生态或部署运维任务。

## 对照设计

A 只有基础工程约束；B 增加常驻设计正文；C 按需读取完全相同的正文。三组使用相同任务、工具、模型快照、推理参数、每等级预算；B/C 正文只有一个定义，不能分别调优。调用 Skill 本身的上下文与成本属于处理效应，不应从 C 中扣除。

维护阶段一律使用新的中性会话、统一维护模型和原始初版快照，不继承开发对话或实验性 Skill。真实 worker 只提供受控的文件和运行工具；不能读取评测器、隐藏案例、未来请求或其他组的产物。原生公开运行和自编测试工具在所有处理组完全一致。

完整默认计划为 24 变体 × 3 处理组 × 3 重复 = 216 条轨迹，最多 648 个阶段。计划先冻结再运行，任务集合、预算、顺序、种子及源码指纹可重建校验。按任务族/语言/重复配对，在语言×等级分层内轮换六种 A/B/C 顺序；三重复时每层覆盖六种顺序。只做一次重复的随附回放用于链路验证，不用于统计推断。

相同语义种子跨语言共享，但语言移植不是新的独立问题。推断按任务族聚类、按语言分开报告；同一模型重复调用也不视为新增独立题目。每层只有两个任务族，置信区间和天花板诊断只能探索性使用，不能产生可靠排行榜。

## 评分和成本

主要观察是初始及两条维护链的契约成功率、所有尝试的总成本。行为测试同时检查旧契约和新增要求。第一阶段失败保留在预先计划的分母中，后续跳过有明确记录。基础设施/适配器故障单独使对应比较无效，不作为模型普通失败，更不悄悄删除。

单独报告 input/output tokens、缓存和推理 token 子集、生成 wall time、工具调用、构建与执行耗时。未知 token 为 null，不记成零；重试不自动发生。模型工具中的编译会占用生成墙钟预算，因此原始跨语言耗时不能直接作能力排名。隐藏验收的编译耗时单独记录，不计入模型推理成本。

生命周期成本采用初始成本 + 0.5×局部维护 + 0.5×扩展维护；这是预定场景权重，不代表真实生产需求分布。实际实验总消耗另列，不能重复计算初版。文件数、代码行数、差异范围仅诊断，不直接判定好坏。仍需盲审具体无关修改和职责泄漏的代码证据，不提供主观架构总分。

## 稳定性与公平性门禁

控制器使用版本化的语言中性契约、确定种子的输入、精确 JSON 语义和独立状态目录。时间由请求中的逻辑时钟提供，不访问网络、真实第三方服务或睡眠竞争。持久化任务真的启动新进程；失败批次检查数据与幂等回执同时回滚。内部持久化格式不限，不检查固定类名、目录结构或层数。

三份原生参考实现与控制器 oracle 分开，但出自同次实现工作，不能称为独立第三方验证。校准包括正向参考、两种布局、固定种子重复、另一种子、反转案例顺序，以及能编译运行但有语义缺陷的负对照；无修改的后续阶段也必须被拒绝。

真实未知代码默认仅允许 Docker，无 Docker 不回退宿主机。模型调用前解析本地不可变镜像 ID，并编译/执行原生探针。限制网络、权限、资源与挂载，保留超时、退出码与输出限制。宿主机运行只用于可信内置参考。当前环境未实际运行 Docker，这些设置不是安全隔离证明；CPU 配额也不等于独占机器。

运行结果封存计划、环境、逐项证据与快照哈希；审查重新计算计数、检查完整题目分配、用例身份、同源分叉、预算和工具链一致性。SHA256 用于检测意外修改或替换，不是能抵御有权限重新封存者的签名。发布的源码与公开题库同样不能证明无训练污染。

## 灵敏度不是靠宣称获得

参考实现通过、负例被拒绝只说明检测器能区分这些已知案例，不能说明题目能区分两个强模型或两种设计策略。sensitivity 输出在 fixture 模式固定为 not_measured；只有真实模型轨迹才产生按语言/等级的探索性天花板或地板告警。阈值 95%/10% 是告警线，不是效度标准，不自动重排难度。

先用冻结模型进行小规模真实试跑，再根据观察决定是否增加更大仓库、更多独立任务族和跨模块维护深度。用于修改题目的数据不得同时作为最终比较的留出证据；更改契约要产生新版本和新计划。参考方案被廉价整体重写时，应记录这种行为，不能为保住架构评分而禁止合理重写。

## 执行顺序

1. 本地运行 pytest、calibrate、reference replay，检查当前机器的工具链和结果封存。
2. 在具备 Docker 与模型凭据的隔离环境完成三种语言的真实 smoke run；先冻结小计划，任何配置变化都重新建计划。
3. 只有 smoke、数据完整性与预算有效后，执行全计划；按语言/等级查看成功和成本，而不是只看总平均。

没有任何有限测试能够承诺绝对稳定、公平或无偏。本版承诺的是明确测试范围、可重复执行、失败时阻止错误结论，以及把尚未验证的部分显式留下。
## 另一个仍需扩展的持久化边界

当前旧数据兼容验证使用题目规定的 legacy.json，而非自动继承每个模型 T0 自创的任意磁盘格式。维护快照继承的是源码；跨快照的任意磁盘状态迁移还没有成为独立门禁。不能据此宣称已验证完整生产升级兼容性。
