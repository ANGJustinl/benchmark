多语言本地评测链路、预定对照和结果完整性机制在本报告所列测试范围内通过验收。**这不是模型实验验收：真实模型调用为 0，Token 为 null，Docker 未实际执行，难度与区分能力尚未实证校准。** 不支持模型或 Skill 排名，也不承诺绝对稳定性、公平性或安全隔离。

## 本轮发现并修复的实质性问题

**未公开需求泄漏。** 审查发现草稿旧代码由多阶段参考实现生成，虽然初始模式不执行未来分支，代码本身仍会暴露未来功能。已改为单独的公开旧代码资产，只包含初始功能；新增 18 个原生编译/运行及关键词防泄漏检查。参考答案仍保留控制器内的多阶段实现，但不进入 live worker 的项目输入。旧的中途验证输出被替换，不纳入发布证据。

**TypeScript 特殊键语义。** 实际复现 `__proto__` 导致 profile 误命中继承属性、幂等回执丢失的问题。改为自有属性检查和安全属性写入；回滚后恢复出的普通对象也同样处理。所有语言共享新增输入，包含进程重启后的特殊键回执；不通过删掉 TypeScript 难例使结果看起来公平。

**错误结果可能被视为有效比较。** 汇总检查逐项事实而非只信 success 字段；基础设施、启动及无效 worker 响应不再被当作普通模型失败。未按计划提供的预算、缺失或重复轨迹、篡改快照，以及重新封存但缺少规定用例的伪造成功都会被拒绝。

**宿主机与容器边界。** 移除了遍历候选状态文件并 chmod 的做法，避免跟随候选产生的符号链接。未知代码没有 Docker 时不回退宿主机。镜像原生编译/执行探针在付费调用前检查；探针源代码在本地主机实跑、Docker 路径以模拟测试验证，并未实际连接 Docker daemon。

## 为什么这些措施仍不是绝对保证

参考实现、输入生成器、oracle 和审查出自同次工程工作，不是相互独立的第三方认证。两种参考布局共享业务逻辑。72 个负控制是已知故障覆盖，而不是穷尽所有缺陷、架构失误或安全攻击。

四个等级是语义复杂度分层，只有两个任务族/层，尚未看到真实强模型的成功率、成本或重写行为；即使全部参考实现通过，也可能存在天花板效应。自动灵敏度报告在 fixture 数据上固定输出 not_measured，不把控制代码全通过包装成有效区分模型。

隔离设置、严格预算、均衡顺序和固定版本只能减少已知干扰。真实模型服务仍可能非确定；共享硬件存在争用；哈希不能防止有权重写全部证据的人重新封存。Docker 镜像安全、真实 API smoke、独占资源/重复机器测试以及未公开任务集都尚未完成。

L4 验证真实文件与进程重启，但不验证同时写入、真实数据库或断电一致性。旧数据兼容使用规范给出的 legacy.json；还没有自动把 T0 自创的任意持久化格式交给 T1 验证。小型 JSON-lines 项目也不能替代真实框架、多服务或大型代码库。

## 使用决策

可用于复现评测器、扩展任务、检查处理条件和准备固定模型 smoke run。**尚不可用于声称哪种模型、Skill 或工程规范更优。** 要形成这类结论，仍需真实隔离环境中的预先冻结实验、更多独立任务族及留出验证；出现天花板应提升真实任务深度，不用文件数或人为架构分制造差异。
